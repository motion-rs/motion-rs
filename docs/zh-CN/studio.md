# Motion Studio

Motion Studio 是一个基于 egui 构建的可选桌面工作台，用于交互式调试编译后的 Rust 场景。即使场景渲染选择 CPU 后端，它也需要原生桌面环境。向 `motion::studio::run(scene)` 传递一个 `StudioScene` 或选择一个项目中的 Timeline 即可启动。Studio 不提供场景列表或窗口内场景切换功能；修改 Rust 源码仍需重新编译二进制。声明式文档是一个例外：详见[热重载](#热重载)。

```sh
cargo run --release --features studio --example studio
cargo run --release -p motion-gallery --features studio,gpu --bin motion-gallery -- studio --demo type-in-motion
```

## 预览与回放

默认主题为中性深灰搭配蓝绿色点缀，并提供浅色模式选项；顶部导航栏中的太阳/月亮图标可随时切换。颜色、间距、圆角与字号均集中于单独的主题模块定义，因此自定义绘制区域会自动跟随当前激活的主题。导航栏还包含预览缩放比例、后端选择器与静音控制（喇叭图标）。原生窗口标题使用场景名称。导航栏最右侧的侧边栏图标用于切换 Inspector 面板的显示与隐藏；在较窄的窗口中默认自动收起。界面不设左侧边栏，也不设多余的“刷新”按钮。底部固定的状态栏实时显示当前选中的后端、显示的帧号以及繁忙指示器，在回放期间保持静止不晃动。悬停在状态文本上可查看完整的后端状态提示。

预览子系统使用有界协调器与可复用的帧渲染槽位。执行时间轴定位（Seek）会暂停回放并丢弃过期的待处理响应。渲染缩放、质量等级、后端以及可选的边界/像素检查共同构成唯一的渲染标识（render identity）。常规 Studio 画面均为透明背景：场景背景、深黑/纯白背景以及棋盘格底色均由 Viewer 视口直接合成，无需重建底层渲染器。资源加载失败会保留占位指示与结构化诊断信息。

回放与时间轴拖拽均使用 Draft（草稿）质量模式。时间轴拖拽以 25% 分辨率快速渲染；释放指针后首先恢复所选缩放比例，静止 150 ms 后自动请求 Final（终版）渲染。Draft 模式使用 0.35 px 容差展平曲线，包括嵌套子树在内仅采样单个快门快照，使用半密度墨迹材质并缩放到设备空间，以及单盒（single-box）模糊近似。Final 模式保持原本的 1/256 px 严格容差、完整快门采样与三盒（three-box）滤镜内核。Studio 导出任务一律强制使用 Final 质量，不受预览质量设置影响。

视图的适应画布（Fit）/50%/100%/200% 缩放与 25%/50%/100% 渲染分辨率彼此独立。鼠标中键或按住空格拖拽平移画布（光标变为抓手状态）；双指捏合或 Ctrl+滚轮以指针为中心缩放，放大后触控板双指滑动可直接平移。Viewer 工具栏使用图标开关控制安全区、网格、节点边界与像素检查器。角落角标显示输出尺寸与当前视口缩放比例。棋盘格背景为单一重复纹理，而非逐个绘制单元格矩形。背景选择、安全区遮罩与网格仅影响屏幕呈现。开启像素检查（Pixels）会触发显式的内存输出与数据回读；检查器报告 sRGB8 和解码后的 SDR 线性值，而非未截断的内部 HDR 工作缓冲区。支持捕获单帧基准图进行双帧 A/B 对比。捕获基准图后可关闭 Pixels 模式以恢复原生 GPU 预览；仅保留基准图并不需要每帧执行 CPU 像素回读。

边界检查（Bounds）使用编译器实际布局与 Z 轴顺序的独立只读快照。拾取检测为基于视觉包围盒的近似拾取，而非精确的光栅化像素覆盖率。Node 选项卡展示元素路径、名称、变换矩阵、滤镜以及局部裁剪/遮罩元数据。检查异常会进入诊断列表而绝不干扰导出。Diagnostics 诊断选项卡最多保留 128 条记录并支持定位到指定帧；当检查结果到达时，匹配的节点路径会被高亮显示。

可调节尺寸的时间轴负责绘制轨道、片段激活区间以及入场转场的重叠区域。标尺自适应调整刻度间距，支持帧号或分:秒展示，时间码显示为 `MM:SS.mmm` 格式。播放指针为带旗标的红线；悬停标尺会显示对应时间、帧号及缩略图。In/Out 控制入点和出点，与导出和循环区间共享（Out 点为开区间）；拖拽标尺上的 In/Out 手柄或使用 Mark In/Out 按钮，区间外的帧会被暗显淡化。按 L 键切换循环状态，与播放栏循环按钮完全等价，不会触发跳转或干扰播放时钟。空格键播放/暂停，左/右方向键单帧步进（按住 Shift 为 10 帧步进），Home/End 跳转至首尾帧。在文本输入获得焦点时会抑制快捷键以防冲突；按住空格拖拽直接平移视口。时间轴上支持在播放指针处添加或移除标记（Cue）；这些纯粹是编辑层面的注释，并非引擎调度的核心 API。后台的 AudioAnalysis 分析线程构建一个 1024 点的 RMS 能量波形，最长分析 300 秒。音频分析失败仅记录为诊断信息，绝不引发视频帧渲染故障。缓存条显示实际保留的帧并将其合并为连续区间。悬停在时间轴上会请求独立的 CPU/Draft/25% 缩略图。独立的 LRU 缓存最多保存 128 张图片和 16 MiB 内存，单图最大 160x90 像素；缩略图的完成绝不替换主视口预览，也不长期锁定 GPU 帧纹理。定位或设置变更会立即取消进行中的缩略图请求并废弃旧代任务。资源加载失败的占位图绝不会作为健康缩略图被缓存保留。

当窗口的 GPU 设备可用时预览优先使用 GPU，否则回退至 CPU；后端选择器仅提供 CPU 与 GPU 两项。GPU 准入失败（包括 `max_bytes` 超额）或设备丢失属于显式强类型错误，绝不会悄然把预览退化为 CPU。后端选择器独立于导出设置控制预览工作线程；切换后端会重建工作线程的渲染器，并使上一个后端的预览缓存失效。帧缓存容量与每帧的 GPU 显存配额彼此独立。

回放严格遵循实时优先策略：点击播放（Play）最多等待其首帧完成（上限 2 秒，其相邻帧会并行渲染），随后立即启动时钟和音频，绝不在播放前预渲染整部短片或等待后续帧。若渲染掉帧，后续请求会跟随音频时钟直接向前推进，不等待上一帧。投机渲染目标会结合当前回放实测的时延进行前瞻预测（冷启动首帧和静止时的 Final 渲染不计入时延统计）；过期的晚到帧会被直接丢弃。当单帧渲染耗时超过帧周期时，当前帧会被直接跳过，因为等它渲染完时针早已走过该时间点。与预览回放截然不同的是，导出流程始终独立、逐帧、无遗漏地渲染每一帧。

回放最多使用 6 个渲染槽位（可用 CPU 核心数减 1，并受 2 GiB 除以单帧最大内存配额的限制）。当缓存空间充足时，投机预测窗口最多在前瞻容纳比槽位数多 1 帧的目标（至少 4 帧）；多槽位池始终为用户的 Seek 操作预留 1 个专属槽位。暂停时的单帧渲染以及低优先级的相邻帧预取每次仅执行一个作业。Seek 或参数设置变更会使过期的任务代次失效；已在执行的回调会在槽位停止前正常执行完毕，但其过期的结果绝不允许对外发布。仅有被请求的主帧会被发布，音频流始终作为回放的主时钟。系统既不引入整片预渲染机制，也不提供其他替代的回放模式。

默认情况下，每个预览会话在各自独占的 GPU 设备上渲染，UI 线程将回读的帧作为预乘的 ColorImage 进行上传。UI 的 wgpu 设备在 UI 线程等待下一个可绘制表面时会持有 Fence 锁，因此直接在 UI 设备上渲染会阻塞预览工作线程的每一次命令提交：在 960x540 分辨率下运行 Signal Garden，单槽位在 UI 设备上每帧需要约 135 ms 且多槽位毫无增益，而在私有独立设备上仅需约 50 ms。设置环境变量 `MOTION_STUDIO_SHARED_GPU=1` 可以切换为直接在 UI 设备上渲染并通过纹理零拷贝交付画面；后文介绍的纹理环（texture ring）机制仅适用于该共享模式。纹理环中的纹理采用 Rgba8Unorm 格式，因为渲染器将编码后的 sRGB 字节直接写入其中；而 egui 采样原生纹理时视其为线性空间并针对屏幕重新编码显示，因此通过相同字节的 Rgba8UnormSrgb 视图进行纹理注册。若缺少该视图，共享模式下的每个颜色都会被二次编码，肉眼可见地变亮，而 CPU 与私有独立设备预览在每通道上均保持在 1 个色阶以内的色彩一致性。

原生输出和工作线程侧预乘的 CPU 上传按每个活动的分辨率/设备共享一个纹理环。纹理环在空闲时保留 3 个槽位，并随着回放窗口自适应扩展（槽位数加上预测帧数再加上正在显示的当前帧，上限 12 帧，受帧缓存预算约束），因此预取的帧在时钟到达之前绝不会被提前逐出。UI 纹理注册通过槽位 ID 复用。仅当针对某张纹理的所有帧租约（Lease）全部释放后，该纹理才可被回收复用；可被逐出的原生缓存条目绝不会永久锁死纹理环。派发任务时在将帧交付给工作线程之前先预留容量，因此并发作业绝不会超额预定纹理环。当所有槽位均处于租用或预留状态时，调度器会选择暂停派发，而绝不回退至全帧 CPU 回读上传。提交或发生错误后预留会被释放；尺寸或设备变更能够安全地退役旧槽位。在无场景 GPU 支持时，UI 会上传预乘的 ColorImage；像素检查则保留其专用的直通 RGBA/回读路径。驱动或 egui 的内部引用以及已退役的租约并不能保证进程总 GPU 显存恰好限制在纹理环大小之内。

预览 LRU 缓存默认提供 256 MiB 的逻辑有效负载上限，不设固定帧数上限。通过环境变量 `MOTION_STUDIO_CACHE_MIB=0..1024` 可覆盖该上限；设置为 0 会彻底禁用缓存保留与预取机制。CPU 像素在缓存与响应之间通过引用共享，命中缓存时无需复制。内存统计涵盖 CPU/GPU 像素负载与条目元数据，但不包含内存分配器与驱动开销、渲染器中间资源或外部持有的帧：这不是进程 RSS 或显存占用的硬上限。在 50% 缩放比例下，一部 8 秒、960x540、30fps 的短片单是 RGBA 像素就大约需要 119 MiB。

工作线程使用与无头（Headless）输出完全相同的 `RenderOptions`/`RenderSession` 契约；`FrameRenderer` 驱动 Composition 的索引时钟。请求诊断信息仍归会话所有；创作期计算以及有界的覆盖率/布局/材质分区在不同预览槽位和设置变更之间全局共享。每个注册的场景拥有隔离的创作分区，panic 或 GPU 设备丢失会使其创作/帧缓存失效。这种恢复逻辑适用于为主帧发布的失败；过期或投机预测产生的失败会被静默丢弃，而不会升级为主诊断异常。显式的像素检查需要内存输出；常规的原生 GPU 预览保持像素全程留在显存中。

在代码实现内部，PlaybackState、InspectorState、ExportState 和 DiagnosticsState 分别聚合各自的控件与观测数据。PreviewState 保持独立：在后台等待新帧完成时，前台可以继续稳定显示上一帧。经过校验的 StudioClock 提供精准的索引时序。这种分组保证了预览工作线程、纹理租约、音频以及导出流水线的析构顺序，不会将并发请求状态混杂。

Stats 选项卡展示实际的工作线程时延、近期呈现/目标 fps（32 帧滑动窗口，启动播放时重置）、缓存命中率、回放掉帧数、逻辑工作量/峰值字节数，以及可选的求值/编译/覆盖率/内存输出耗时、工作线程上传排队耗时与原生准备/提交墙钟耗时。CPU 内存输出为融合操作，不拆分测量合成与色彩转换。原生 GPU 提交保留各自的观测数据与工作线程从提交到完成的端到端时延；这些是 CPU 墙钟维度的观测值，而非 GPU 底层时间戳查询、系统 RSS 或验收基准数据。无头渲染会话默认禁用阶段时间测量。

原生预览输出直接读取最终的 RGBA32F 工作纹理，无需完整分配线性浮点输出缓冲区或执行专门的 resolve pass。裁剪原点、延迟的 Plus alpha、有限值检查以及 RGBA/BGRA/半精度浮点目标格式契约均得到完整保留。原始保守的逻辑字节/工作量配额保持不变。帧完成与发布策略也维持一致；这不是额外的帧级流水线化。

若需在命令行无头测试 Gallery 短片上的相同 submit/finish API 性能：

```sh
MOTION_BENCH_TEXTURES=1 MOTION_BENCH_BACKENDS=gpu \
MOTION_BENCH_CASES=type-in-motion MOTION_BENCH_QUALITY=draft \
MOTION_BENCH_SEQUENCES=1 MOTION_BENCH_SEQUENCE_FRAMES=240 \
MOTION_BENCH_VIDEO=0 MOTION_BENCH_FONT=tests/fixtures/fonts/NotoSans-Regular.ttf \
cargo bench --locked --offline -p motion-bench --bench films --features gpu
```

纹理模式需要不含视频编码的纯 GPU 序列测试；质量默认为 `draft` 或显式指定为 `final`。它记录每个连续帧从准备到提交、再到等待完成的完整延迟。三个原始 RGBA 参考基准帧在计时区间外执行回读。序列包含 240 个样本，独立于安装测量的 `MOTION_BENCH_SAMPLES`。校验和编码了帧顺序，而非逐个检查渲染像素。这些是没有窗口、缓存环、回放调度器、显示延迟或丢帧观测的纯 CPU 墙钟测量；切勿将其汇报为 Studio 屏幕呈现的 FPS，也不可当作完整的视觉验收测试。

时间轴传输保持精确的有理数帧率。当音频激活时，实际播放的可听采样驱动视频画面的时钟推进。音频准备过程会暂时保持当前图像；缓冲区欠载（Underrun）、设备故障或时间戳异常会暂停画面，而绝不悄然退化为依靠系统墙钟推进。静音仅影响当前预览。空音频混音不会打开任何音频输出硬件。

Timeline 音频与配置的本地音频文件在同一混音管道中表现为 AudioClip 实例。音频工作线程通过 MixedAudio 在每个时间窗口内最多准备 8192 个输出采样；音轨偏移与片段局部淡入淡出在多个时间窗口以及导出区间裁剪之间平滑延续。文件解码使用与无头导出相同的延迟解码器，解码过程不在硬件设备回调中执行。当前音频硬件输出固定要求 48 kHz 双声道 f32 格式。在 In/Out 点之间循环播放会重新初始化音频准备，且无法绝对保证完全无缝（gapless）。

## 导出与会话持久化

Inspector 选项卡（Export、Node、Diagnostics、Stats）由四个等宽的带工具提示图标按钮组成。Stats 将参数归类为 Playback、Preview worker、Cache 和 Frame cost 四大板块。Stats 右上角的无边框复制图标按钮可一键将当前显示的所有段落、数值、单位及 GPU 时间戳以纯文本格式复制到系统剪贴板。Diagnostics 同样在右上角提供清空诊断列表的图标。右侧的 Export 面板支持将 H.264、H.265、带 Alpha 的 VP9、ProRes 4444、PNG 序列帧、GIF 以及单帧 PNG 静帧加入导出队列。预设包含 1080p H.264、透明 ProRes 以及 640x360 GIF。GIF 与 PNG 序列显式静音；GIF 默认采用时间轴帧率（最高 100 fps），其余情况下默认 30 fps。队列最多容纳 16 个串行运行的任务，每个任务保存提交时分辨率、区间、后端、快门、编解码器与音频配置的独立快照。排队中的任务可被移出队列；当前正在执行的任务支持协作式取消。最多保留 64 条完成记录，附带强类型错误信息与“打开所在文件夹”操作。流式文件音频生效时，分辨率、区间、后端与快门设置依然起效。选定的时间范围能够正确保留片段局部的音频淡入淡出。导出 PNG 忽略音频配置。

Export 表单仅保留瞬态参数（尺寸、范围、后端、快门、编码器选择）；经一次参数转换生成 `export` 函数所消费的 `ExportOptions`。`StudioScene` 持有单一的 `Timeline` 供预览、音频回放与导出共享，外部音频文件由混音器统一解析。

导出作为独立流程运行，保留类型化错误并遵守协作式取消约定。关闭 Studio 窗口会丢弃排队任务，取消活动作业，并安全等待资源清理完毕。已存在的输出文件仅在导出成功结束且获得显式覆盖授权后方可被原子替换。

会话状态持久化存储于 `.motion/studio.json`，记录有界的场景、当前帧、预览缩放、区间及标尺标记，重新打开时绝不自动开始重放或导出。音频配置可单独保存与加载；引用的外部媒体资源仅保存路径而不内嵌数据。

本设计刻意不包含参数动态修改、穿梭轮快捷键/命令面板、可停靠浮动面板、音频摩擦轮监听（Audio Scrubbing）以及 Debug 构建警告。会话持久化不是停靠面板系统的实现。

## 热重载

通过 `StudioScene::reloadable(watch, load)` 注册的场景支持在工作台运行期间动态重载。`Project` 为声明式文档默认注册了热重载：执行 `studio film.json`，或使用 `Project::document` 添加的 Timeline，会自动监视该文档及其引用的所有外部文件。被监视文件的修改时间与长度以每秒 4 次的频率被轮询；一旦文件变更静止超过 200 ms，工作线程便会自动执行 `load` 重新加载。

重载成功会无缝替换当前场景，并保留播放指针位置、标记点、预览设置与导出配置（自动截断到新时长范围内）。已缓存的帧会被清空，回放自动暂停。重载失败会保留上一版本的有效场景，在顶部导航栏显示错误并添加至诊断列表，因此编辑过程中半保存的临时文件绝不会导致预览画面变黑崩溃。文档重载成功会实时更新受监视的文件依赖列表，包含新引用的资源文件。编译期间检测到的新修改会直接作废旧的中间产物并排队等待全新重建。已经排队或正在运行的导出作业保持使用其启动时的场景定义。通过 `MOTION_STUDIO_SHARED_GPU` 请求的单场景 GPU 上下文仅对启动初始场景生效。

参考：[Gallery 展厅](../../gallery/README.md)、[渲染契约](design/rendering.md)与[可靠性规范](design/reliability.md)。工作线程层面的测试不能替代物理 UI 点击、真实音频硬件、跨显示器缩放或跨平台驱动崩溃恢复的手动验证。
