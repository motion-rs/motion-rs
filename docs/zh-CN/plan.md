# 开发规划

本规划阐述了项目的后续待办工作，而非历史实现变更记录。
任务在每个优先级内按顺序排列。正确性质量门禁优先于性能优化。

## 可靠性与 API 质量

1. 保持各子包的测试独立于 facade 对其自身 crate 的依赖副本。验证最小特性、默认特性、无场景 GPU 的 Studio 以及全特性构建；在每种受支持的配置下运行常规测试和 Rustdoc 示例。
2. 持续维护字体、GPU 和 H.264/AAC 的显式测试固件。检查像素一致性、精确的 Seek 定位重放、任务取消、设备丢失恢复、源文件防覆盖保护以及临时文件清理。被忽略的固件测试必须具备具名执行用例。
3. 确保公开 API 契约完备：物理单位、默认值、错误类型、资源所有权、多线程模型、不支持的输入判定，以及逻辑内存与物理显存限制的区别。在 CI 中严格拒绝失效的 Rustdoc 链接和过时的源码引用。
4. 将现有的 Linux/macOS 特性矩阵 CI 拓展至 Windows 平台与独立显卡适配器运行环境。建立平台特异的字体/音频/FFmpeg 环境配置，将环境级故障与算法回归区分开来。macOS 上的测试结果并不代表其他宿主平台已经达标。
5. 提升 Studio 交互测试覆盖率：快速 Seek 定位、窗口尺寸调整、场景/后端动态切换、回放或导出时的热重载、静音切换、音频欠载容错、导出期间关闭窗口以及显卡设备恢复。自动化的工作线程固件无法完全替代实际窗口环境与音频硬件的验收测试。

## 性能优化

基准测试的工作负载、执行命令与历史记录均位于[性能基准](benchmarks.md)；所有测得的阶段结果保留在[当前实测数据](benchmarks.md#当前实测数据)中，对比上一阶段和初始基准线的变化。禁止为每个单步阶段创建单独报告。现存的既有契约见[渲染设计](design/rendering.md)与[架构设计](design/architecture.md)。

已获批准的底层 API、校验完备的 `try_*` 替代方案、迁移注意事项、仅用于测试的音频参考固件或可选的 LaTeX/磁盘缓存扩展，不得作为弃用的兼容路径。

### 验收流程

1. 使用[基准测试流程](benchmarks.md#非短片全量基准重测)针对受影响的工作负载建立经验证的当前源码基线，切勿使用已删除的历史耗时数据。
2. 校验上述任务专属的边界条件，并记录实际运行的验证命令与源码 Git 提交哈希。涉及视觉画面变更的提议需要单独审批。
3. 遵循[报告更新规范](benchmarks.md#更新流程)登记测量结果、回归项与验证范围。常规测试、基准数据与原生硬件验收属于彼此独立的质量门禁。

### 验证技术债

- 极简特性配置下的 content 单元测试门禁仍通过 asset/vector 测试引用纯文本/字体固件；独立的消费者编译通过并不等同于单元测试覆盖充分。
- `motion-content`、`motion-encode`、`motion-render`、`motion-formula`、`motion-scene`、`motion-studio` 和 `motion-gallery` 的独立特性集合均已通过库构建与零警告 `--all-targets` 检查。`motion-rs` 库目标在无额外特性下零警告编译，但仍有若干集成测试和示例在缺失特性时无法编译；需补充 `required-features` 或针对单个测试设置特性门控。
- Windows 平台、独立显卡以及 Studio 实际窗口/音频设备的物理交互仍需显式运行时验收。现有的 Linux/macOS CI 与离线测试无法代替这些验证。Studio 循环快捷键已有回归测试，但仍需在原生 UI 环境下验收。

## 特性拓展规划

### 独立 GPU 准备路径

v3 后端解耦已经规范化了 FrameIr 语义与独立的 CPU/GPU 准备产物。FrameIr 保留已准入的 f64 设备空间曲线、Wang 线段上界、有序作用域、画刷、裁剪与滤镜域，不包含具体的覆盖率。符合条件的 GPU 曲线直接在显卡设备上展平至静态有界的边存储，随后在 GPU 上直接生成 f32 覆盖率，无需生成 CPU 侧的 PreparedCpuFrame。GPU 覆盖率采用有界的 16x16 tile 分箱并带有符号的行进位累加。准备报告暴露出线段/tile 计数、几何上传字节数以及结构化的显式不支持路径错误（绝不隐式回退到 CPU 覆盖率）；GPU 启动自检同时运行 CPU/GPU 独立准备路径并进行画面对比。不可变图像、Mipmap 和 Atlas 纹理具备跨帧的有界上下文局部驻留机制。符合条件的解析粒子直接在 GPU 上生成消费的图元记录；对于不受支持或精度不足的情况仍保留 CPU 实素化。网格渐变与程序化氛围画刷保留描述符，在 CPU 与 GPU 上分别独立求值；显式图像烘焙 API 保留现有行为。待完成的验收项包括：

1. 添加大型复杂场景原生测试固件，复用 Breadth 基准场景：文本排版、带渐变/孔洞/裁剪与滤镜的 SVG 路径、嵌套裁剪下的相交路径，以及带有模糊、网格渐变与程序化氛围的解析粒子。在 640x360、1920x1080 和 3840x2160 下渲染多个帧，根据[视觉验收](design/reliability.md#视觉验收标准)档位进行对比，且每次重放前均先执行一次不相关的 Seek。该测试需要显式的逻辑字节配额，不得更改 Breadth 基准的原有预算。
2. 将其余 CPU/GPU 对齐固件（Bloom、文本、FrameRenderer 会话、粒子与程序化画刷）从局部单通道或 f32 容差对比迁移至标准视觉验收档位，跨 crate 共享比较算法。将 `VisualCheckPolicy::max_rgb_difference` 与视觉验收档位对齐。
3. 在宣称性能提升前，先在更高分辨率下充分验证复杂文本、SVG、复杂裁剪与滤镜场景。GPU 曲线展平、程序化求值和内存驻留的功能完备并不等同于吞吐量已经达标。

### 更多引擎能力

1. 扩展视频输出编解码器/预设、支持 Alpha 通道的格式以及色彩管理选项。每种组合需具备显式能力检测与解码后输出验证固件。
2. 仅通过共享的矢量/滤镜模型扩展 SVG 和滤镜支持。不受支持的语法语义一律作为诊断信息报告，绝不静默以错误光栅化替代。
3. 引入可变字体（Variable Fonts）、彩色字形（Color Glyphs）格式以及更丰富的文本修饰能力，保证源码和字素簇的一致性。保持单一段落排版引擎与显式固化的字体快照。
4. 增加音频设备、采样率和通道选择功能，支持无缝循环与流式音频分析。保持离线确定性计算与实时音频硬件控制的边界隔离。
5. 扩展粒子力学模型与通用力场/模拟算子，优化密集邻域查询。具体的烟雾/火焰艺术实现保留在应用层，不侵入核心库。
6. 探索逆运动学（IK）/骨骼约束、更丰富的程序化材质以及工程文件持久化。必须先定义好有界的资源、时间、错误处理与缓存契约。
7. 向共享矢量模型添加路径布尔运算（并集、交集、差集、异或）。计算结果必须保持确定性，通过 `Budget` 和 `RasterLimits` 严格限制开销，且在 CPU 与 GPU 后端上表现完全一致；退化退化与自相交输入需具备显式测试固件与诊断报告。
8. 添加网格渐变（带有点颜色的 Patch 网格）。在分配内存前先准入 Patch 和细分数量，明确定义色彩空间与插值方式，保持 CPU 后端、GPU 计划、WGSL 着色器与主机 ABI 严密对齐。
9. 引入 2.5D 平面透视：利用摄像机、深度排序与透视正确采样在 3D 空间中变换图层，同时避免将引擎膨胀为全功能 3D 渲染器。定义一次投影、裁剪和背面剔除行为，保证 CPU 与 GPU 像素级一致。
10. 添加基于 `motion-ffmpeg` 解码的视频输入源。时间轴时间显式映射至源视频帧，确保 Seek 精确重放。严格限定解码内存、不支持的编解码器与可变帧率故障处理，以及音频分离提取。解码器仅加载通过 `Assets` 显式指定的路径。
11. 引入硬件加速视频编码（如 VideoToolbox、NVENC、VAAPI）作为显式的可选编码器。使用前先检测硬件支持能力，不可用时明确报告而非静默降级为软编；保持软件编码作为确定性基准参考。每个硬件编码器需配备解码输出测试固件与具名的被忽略执行用例。

## 声明式文档

文档格式规范、参数系统、属性绑定、内容类型、热重载与诊断规则详见[声明式文档设计](design/documents.md)。后续演进按序推进：

1. 补齐内容能力差距。粒子系统缺少图像发射器、外力场、Sprite 精灵表、散景虚化与拖尾选项；数学公式缺少子表达式拾取；Typst 多页排版文档、动画 SVG 与序列帧图像输入尚不支持声明；音频系统缺少由分析驱动的动态信号、音频合成、变速/倒放变换、元数据与章节标记。
2. 扩展属性绑定：读取元素的全局变换矩阵和包围盒，支持跨 Scene 以及与音频分析结果绑定，支持引用完整点位（`@id.position`）而非仅单分量。
3. 建立文档版本迁移机制：新增 `migrate` 子命令及向后兼容规则。在第二个格式版本出台前，其他版本直接拒绝。
4. 评估 Lottie/Bodymovin 格式导入器，将其作为到本格式的转换器。在严格审查许可证和二进制体积后，决定采用现有 Rust 开源实现或自研官方子集，保持该依赖完全可选。
5. 为具备数据形态的 Builder 提供将代码构建的 Timeline 导出为文档的功能。由于闭包形式的 Scene 无法序列化，必须清晰划定可支持的子集边界。
6. 采用 Fuzzing 模糊测试与属性测试强化解析器和编译器（零 panic、有界工作量、所有诊断路径均可解析），并为示例文档在两个后端上固化黄金标准帧。
7. 将保留诊断信息的上限（256 条）改为可配置项。
8. 热重载细节打磨：在重载期间保留单场景的 GPU 上下文，在真实宿主设备上完成原生窗口交互验收。现有的自动化测试使用无头 egui，无法完全替代真实环境。
9. 扩展静态 Schema 范围校验，不仅限于文档时间和粒子输入。动画求值结果和外部资源的可用性依然依赖运行时校验。

## 完备性验收标准

每项代码改动必须包含针对性的断言，并通过相关 package/feature 的编译、常规测试、文档测试以及显式的环境测试固件验证。任何性能或硬件支持相关的宣称必须附带实测数据证据。在源模块内保持内联测试，直到代码超过约 300 行时再迁移至同级的 `tests.rs`（参见[代码风格](style.md)）；严禁为简化测试而移除独立的断言。
