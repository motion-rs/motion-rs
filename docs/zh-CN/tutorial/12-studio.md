# 12 Motion Studio

## 本章学习目标

在桌面交互式工作台中自省编译后的场景，实时调试视口预览、实时回放、音频监听与多任务导出队列中的各类问题。
本功能需要开启 `studio` 特性与原生图形桌面环境；该特性隐式开启 `ffmpeg`。场景的显卡渲染需要开启 `gpu` 特性，但基于纯 CPU 渲染的场景同样可以直接在窗口中正常显示。

## 最小可运行示例

```rust,no_run
use motion::prelude::*;
use motion::render::Composition;

fn main() -> motion::Result {
    let timeline = Timeline::new(Size::new(640.0, 360.0), FrameRate::NTSC).track(|track| {
        track.scene(4.seconds(), |context| -> motion::Result<_> {
            Ok(RoundedRect::new(Rect::new(180.0, 100.0, 460.0, 260.0), 12.0)?
                .fill(Color::rgb(35, 155, 130))
                .rotate(context.seconds() * 0.6))
        })
    }).build()?;
    motion::studio::run(motion::studio::StudioScene::new(
        "tutorial",
        Composition::new(640, 360, motion::render::FrameClock::new(fps!(30), 150)),
        timeline,
    )?)
}
```

运行程序会直接打开该单一场景，而非弹出场景目录列表。修改 Rust 源码需要重新编译，界面不支持动态编辑参数。声明式 JSON 文档是一个例外：通过 `studio film.json` 打开的文档在保存时会自动就地热重载并保留当前播放指针位置（参见 [热重载](../studio.md#热重载)）。

也可以直接在仓库根目录下运行现成示例：

```sh
cargo run --release --features studio --example studio
cargo run --release -p motion-gallery --features studio,gpu --bin motion-gallery -- studio --demo type-in-motion
```

## 工作台核心功能区域

| 界面区域 | 检查与控制功能 |
| --- | --- |
| 顶部导航栏 / 视口 Viewer | 切换渲染后端、设置渲染缩放比、静音、主题切换、画布缩放与抓手平移 |
| 底部时间轴 Timeline | 浏览轨道、片段、转场重叠区、播放指针、设定 In/Out 入出点、打标记 Cue |
| 导出面板 Export | 配置视频格式、输出分辨率、时间范围、查看任务队列与协作式取消 |
| 节点检查 Node | 自省节点路径、实际排版布局、Z 轴层级、变换矩阵与局部裁剪 |
| 诊断面板 Diagnostics | 聚合外部资源、排版测量与执行异常；点击具体条目可直接跳转至对应帧 |
| 统计面板 Stats | 观测工作线程时延、呈现/目标 FPS、缓存命中、掉帧数、逻辑工作量与峰值 |

若需诊断特定片段，请先暂停播放并跳转到对应时刻，开启 Bounds 边界框或 Pixels 像素检查，随后查看诊断列表与统计数据。Bounds 提供的是基于视觉包围盒的拾取，而非精确的光栅化像素覆盖率。

## 渲染分辨率与视口缩放

25%/50%/100% 渲染缩放比例控制的是实际渲染出的物理像素量；而适应视口（Fit）/50%/100%/200% 视口缩放仅改变屏幕上的展示比例。强行放大低分辨率的预览不会带来任何画质提升。

底色选择、棋盘格、安全框与网格均属于 Viewer 屏幕呈现层的功能，绝不改变最终导出的短片文件。常规预览始终保留透明通道，因此切换背景颜色绝不触发底层渲染器的重建。

回放与拖动时间轴统一采用 Draft 草稿质量模式。拖动时以 25% 分辨率快速求值；松开指针后首先恢复所选分辨率，静止 150 ms 后自动请求 Final 终版渲染。Draft 模式采用近似算法展开曲线、合并快门采样与模糊计算。正式导出任务始终强制使用 Final 终版质量。

## GPU 原生零拷贝、像素检查与 A/B 对比

常规的原生 GPU 预览直接将渲染完成的显存纹理注册至同一个 eframe 设备中显示，彻底规避了全帧 CPU 回读与显存二次上传。纹理环在向工作线程派发任务前会先预留显存槽位。当所有槽位均处于租用状态时，调度器会暂停派发，而绝不悄然退化为 CPU 像素路径。

Pixels 像素检查开关会显式触发内存输出与数据回读。检查器报告 sRGB8 和解码后的 SDR 线性值，而非未截断的内部 HDR 工作缓冲区。捕获单帧作为 A/B 对比基准图后，可随时关闭 Pixels 模式以恢复高效的原生 GPU 预览；保留基准图并不需要每帧继续执行 CPU 回读。

## 实时回放不等于单帧验收通过

点击播放会立即启动时钟推进，而绝不预渲染整部短片。当渲染掉帧滞后时，渲染目标会自动前瞻跳步，过期的旧帧会被丢弃而不予显示。执行 Seek 跳转会立即暂停播放并作废旧代任务。已在执行中的回调函数会正常结束，但其过期的产物绝不允许覆盖较新的请求。

目标 FPS、近期呈现 FPS、缓存命中数、掉帧数与工作线程耗时是彼此独立的指标。缓存命中带来的丝滑回放不能证明冷启动全量渲染同样具备相同帧率。

预览模式明确选择 GPU 或 CPU；GPU 硬件故障会记录强类型错误，绝不会悄然退化为 CPU。

## 多级缓存与伴音驱动

视口预览 LRU 缓存默认保留 256 MiB 的逻辑有效负载。通过环境变量 `MOTION_STUDIO_CACHE_MIB=0..1024` 可动态调节；设置为 0 会彻底禁用帧保留与相邻帧预取。这并非进程物理 RSS 内存或总显存上限。

时间轴悬停缩略图使用独立的微型 CPU/Draft 缓存，既不占用主 GPU 纹理环槽位，也不干扰主视口画面。渲染器的覆盖率、排版与材质缓存独立于全帧 LRU 缓存。

当音频激活时，实际播放的可听采样直接驱动画面时钟推进。音频准备过程会暂时保持当前图像；缓冲区欠载、声卡断开或时间戳异常会暂停画面，而绝不悄然退化为依靠系统墙钟推进。空音频流不会打开物理声卡，静音仅影响当前扬声器监听。

## 多任务导出队列与工程持久化

在将任务加入导出队列前，请先配置好分辨率、In/Out 入出点、后端、快门与编解码器。任务独立保存参数快照并在后台串行执行。预览时的跳步掉帧绝不影响导出任务中对每一帧的精准完整渲染。

取消任务或关闭 Studio 窗口遵循协作式取消约定，并安全等待资源清理完毕。已有文件仅在最终成功导出并获得显式授权时才会被原子替换。预览与导出是两个独立的流水线；预览成功并不代表音频编码或最终文件落盘必然成功。

会话状态保存在 `.motion/studio.json` 中，重新启动时绝不自动重播或触发导出。音频配置不内嵌外部媒体文件，也不构成独立的项目工程。

## 常见踩坑点

- 误将 Debug 模式下的回放延迟等同于 Release 优化后的真实性能。
- 误把开启 Pixels 检查后引发的 CPU 回读开销当作常规 GPU 预览的正常表现。
- 误将设定目标 FPS 等同于实际呈现 FPS，或把缓存命中误判为全新渲染出的画面。
- 误将 Studio 的静音按钮等同于从导出视频中彻底移除音轨。
- 假定在当前机器上打开窗口成功，就证明在所有操作系统平台上声卡驱动、显卡缩放与崩溃恢复均已达标。
