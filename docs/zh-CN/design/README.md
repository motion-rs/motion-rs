## 设计词汇表

文档在全局严格、一致地使用以下术语；Rustdoc 负责定义具体的类型签名。

| 术语 | 含义与定义 |
| --- | --- |
| Timeline (时间轴) | 拥有固定帧率与逻辑尺寸的多轨道场景容器 (`Timeline`) |
| Scene (场景) | 接收场景上下文并纯函数式返回指定时刻 Node 快照的闭包或结构 |
| Node (节点) | 不可变创作快照的基本元素；各种 Modifier 修饰器返回全新的 Node |
| Project (项目) | facade 层的项目注册中心 (`Project`)，负责管理具名 Timeline 并提供 CLI 入口 |
| Composition (合成) | 底层固定输出配置的渲染器 (`Composition`)，可与单个 Scene 或整个 Timeline 配合使用 |
| Display list (显示列表) | 从 Node 树编译生成的经过验证的扁平绘制指令序列 (`DisplayList`) |
| Frame IR | 内部已准入的设备空间曲线、有序作用域、画刷、裁剪与滤镜域，不包含具体的覆盖率数值 (`FrameIr`) |
| Prepared frame (已准备帧) | 包含 CPU 覆盖率、画刷记录与准备统计数据的结构体 (`PreparedCpuFrame`)；GPU 准备产物拥有独立的专用结构 |
| Backend (后端) | CPU 后端或 GPU 后端；GPU 会话可在显卡设备上独立生成填充覆盖率 |
| Still (静帧) | 单个已渲染的画面帧，可保存为图片文件或以内存位图形式返回 |
| Film (短片) | 导出的完整视频文件，包含或不包含混音音频轨 |
| Look (风格外观) | 可复用的渲染风格配方 (`Look`)，将场景侧的 `SceneEffects`（滤镜、快门、胶片抖晃）与输出侧的 `DisplayTransform` 绑定 |
| Document (文档) | 对 Timeline 进行版本化描述的纯数据声明式 JSON 文件 (`motion::declarative::Document`) |
| Studio | 用于预览调试已编译场景的专用桌面工作台（大写 Studio） |

## 目标与非目标

Motion 是一个面向代码的 2D 视频引擎：以确定性纯函数计算精确时间点、合成动画几何与多媒体内容，并生成高质量静帧或时间保序的编码视频流。预览与导出完全复用同一套创作出的 Timeline。逻辑设计坐标独立于最终输出分辨率。可选特性显式暴露出对应能力，绝不悄然隐式挑选设备、扫描系统字体或打开窗口。

Motion 明确不是 3D 模型渲染器、不是浏览器运行时、不是通用 UI 布局引擎，也不是交互式拖拽关键帧编辑器。Studio 仅用于预览编译后的 Rust 场景；修改 Rust 代码依然需要重新构建，但声明式 JSON 文档支持原地热重载。Studio 启动时仅加载单个场景，不支持窗口内切换多场景。声明式[文档系统](documents.md)描述纯数据 Timeline；它不会将属性动态绑定到 Rust 原生闭包。`Transform` 保持为仿射变换。平面 2.5D 透视严格限定于 `Perspective`，它负责投影路径几何形状；光栅化图层与位图图像不执行全透视纹理映射。

## 核心设计原则

1. **画面是显式时间与固定输入的纯函数。** 有界的各级缓存保留基于完整键的中间结果，绝不保存包含隐式可变状态的回放历史。
2. **统一的创作模型输出不可变 Node 快照。** 共享的叶子节点复用静态准备结果，同时允许定制化回调充分动态求值。
3. **Trait 面向开放扩展点。** 如 Scene、Drawable、DeferredContent、Asset、AudioSource 与 Encoder。封闭的指令/后端协议一律使用详尽的穷举式 enum。
4. **后端中立的帧事实先于后端感知的准备阶段。** 符合条件的 GPU 填充使用设备端展平的曲线或线段上传并在 GPU 上生成覆盖率；其余覆盖率保留在 CPU 侧。独立的 GPU 路径不等于必然的性能提升。
5. **统一矢量流水线。** SVG、文本排版与 Typst 数学公式共享底层的矢量几何、滤镜效果与覆盖率计算设施，而非分裂为各自独立的渲染引擎。
6. **数值与资源契约具备严格的显式边界。** 同一环境下的确定性重放并不承诺跨平台或跨显卡设备获得逐像素逐比特完全相同的输出。
7. **强类型错误完备保留原因与帧上下文。** 文件落盘提交、内存目标安全替换与就地外部纹理具有截然不同的事务性保证。

公开 API 一律采用完整、自解释的英文命名，保留行业公认缩写（如 GPU、SVG、RGBA、YUV）。资产类型清晰区分解码后的裸数据与可绘制内容。组合子方法在可行时与其功能定义就近放置；共享数据结构通常满足 `Send + Sync`。Facade crate 的职责是装配对外的公开命名空间，而非充当另一层繁冗的实现抽象。

## 风险与未决事项

| 潜在技术风险 | 既定防御边界与应对方案 |
| --- | --- |
| CPU 准备耗时制约 GPU 吞吐量 | 独立测量准备阶段 Profile；任何新的缓存策略与算术快速路径必须具备充分的正确性与计时收益证明 |
| 频繁重复构建 Node 节点与 Path 路径 | 保留基于完整键的不可变准备产物；切勿试图以渲染帧历史替换动态场景的求值 |
| 极端退化的描边与高曲率几何 | 恪守结构化限制配额、参考实现严格比对以及确定性的失败处理 |
| 外部字体、编译器或显卡驱动变更 | 固化测试输入、记录报告运行时环境特征并重新运行适用的测试固件门禁 |
| Typst 上游依赖版本颠簸 | 严格封装编译器内部细节，采用环境感知的有界缓存 |
| 原生编解码器环境缺失 | 编译时依赖原生系统开发库与编解码器；PNG/GIF 为独立实现，而非命令行子进程退化 |
| 预览实时交互与音频硬件交互 | 严格限定工作线程生命周期；真实显示窗口与音频硬件的验收与离线自动化固件严格解耦 |

历史里程碑的设定不代表当前性能的硬性保证。本设计绝不宣称全场景 GPU 必然加速、1080p 必然实时渲染、进程 RSS 内存绝对固定，也不宣称已在全平台各显卡上完全验收。当前的实测客观数据记录在性能基准报告中；尚未补齐的门禁保留在规划文档中。

## 文档维护约定

在每个 0.x 版本发布前，仔细对照底层源码实现核对文档契约、特性转发、被移除符号与迁移说明。独立校验本地链接与代码示例，与运行时/后端验收区分开。涉及像素计算、几何算法、任务调度或对象生命周期的修改，必须配备适用的重放与原生测试固件，而绝不能仅靠静态文档审查。将各项具体契约保留在其专属的主题文档中并互相引用，避免在此处冗余复制代码声明、基准表格或完成清单。
