# 系统可靠性契约

## 校验与故障模型

Composition 的预检（Preflight）阶段仅校验尺寸与时间范围，绝不求值场景内容或创建 GPU 硬件设备。Node 节点的测量与编译负责校验结构性属性；准备与渲染阶段独立应用光栅化计算量与活跃字节配额。隐藏的无效内容绝不会被悄然跳过。用户自定义的闭包函数被视为受信任的纯代码，而非沙箱隔离代码。

默认的光栅化准入使用 `RasterLimits::authoring()`，不设工作量上限；`RasterLimits::sandbox()` 保留可选的 2 亿工作量单位上限。像素与活跃字节限制以及显式声明的工作量上限始终强制执行。导出并发根据第一帧测得的逻辑峰值与有界槽位分配线程，并在后续帧超出单槽位预算时无缝回退为串行重试。这既不是超时时间线，也不是进程物理内存的沙箱隔离。

错误对象 `Error` 完备保留错误分类、可选的发生帧号以及原始底层错误源。在编程处理时，应当检查 `kind`、`frame` 并通过 `downcast_ref` 匹配具体类型，而非解析字符串文本。同步回调中的 panic 会直接向上冒泡；跨越后台工作线程边界时会被捕获并转化为场景 panic 诊断信息。失败的不可变帧在修正输入后可随时重试，绝不产生部分写入的残缺输出。库级别的互斥锁保护的是在每条语句执行后均保持合法的纯数据，因此当工作线程发生 panic 导致锁中毒时，`motion_core::sync` 会恢复纯数据状态安全继续执行，而非直接引发二次 panic 崩溃。唯一的例外是字体排版引擎：其第三方塑形状态在 panic 后无法保证内存合法，因此中毒的字体引擎会显式返回校验错误。

`ValidatedDisplayList` 保留一份经过校验的不可变指令快照，并不代表后端硬件可用或光栅化预算一定充足。图像画刷引用不可变的像素切片，不存在延迟执行的外部图像生成闭包。Preflight 预检无法保证任意用户回调必然不触碰设备或计算有界。

## 错误返回类型分工

| 错误类型 | 返回该类型的 API | 含义与设计意图 |
| --- | --- | --- |
| `ValidationError` | 构造函数、`try_*` 方法、值 Builder 的 `build`（如 `Spring`、`Oscillator`、`Path2D`） | 标明单个非法属性及其结构化路径；不包含帧号上下文 |
| `ErrorReport` | `TimelineBuilder::build`、`ProjectBuilder::build` | 在组装 Timeline 或 Project 期间收集到的所有致命错误集合；操作失败 |
| `Diagnostics` | `Timeline::diagnostics` 与场景求值过程 | 附加在已构建对象上的非致命警告与记录的异常信息 |
| `Error` | 渲染、导出与 I/O 流程（`motion::Result`） | 包含错误分类（`kind`）、可选帧号及原始底层错误；包装了上述三种类型 |

Scene 场景闭包可直接返回 `Result<Node, ValidationError>`（任何实现 `IntoSceneOutput` 的类型均可），因此形状构造函数上的 `?` 运算符可直接冒泡为帧级错误，无需为此提供对应的非 Result 构造器。

## 所有权与事务安全

外部资源表现为显式的不可变快照。缓存的唯一性包含所有可能改变解码或排版结果的运行环境。字节与条目限制约束的是逻辑常驻有效负载，而非进程的物理 RSS 内存。场景求值回调执行期间绝不会隐式触发系统字体扫描或显卡设备初始化。

每个新创建的 `Assets` 拥有独立的 `ResourceStore`，除非显式指定共享。`RenderSession` 拥有各级缓存，并在每次请求时挂载全新的 `RequestDiagnostics` 收集器；`Handle::get_with` 支持将资源错误传播至显式的跨线程收集器中。`DrawContext` 显式传递该收集器；旧有的 FrameAssets 全局桥接已被彻底移除。捕获的句柄通过 `get_with` 访问，不再依赖隐式的全局状态。`RenderOptions.gpu_context` 是显式的 GPU 设备注入点；`RenderContext` 存储资产与结构化策略。外部传入的 GPU 输出纹理必须与当前选定的物理设备和经过校验的目标格式严格匹配。失败的命令提交绝不发布半成品的残缺预览。

系统字体元数据采用延迟索引；追求确定性的项目应当注册显式不可变的字体文件字节。`ExportReport.fonts` 仅审计实际被使用的字体源哈希，不保证跨平台的逐像素光栅化一致性，也不是文件的密码学哈希。

视频文件导出采用临时文件过渡写入，仅在编解码器成功终结后执行一次性原子提交覆盖。在该时间点之前发生的任务取消会完整保留原有目标文件并清理临时暂存文件。任务取消不会立即强行打断阻塞的底层系统调用。流式输入媒体在导出期间必须保持可用；输出目标路径与输入数据源冲突时会被直接拒绝。

内存渲染目标仅在当前帧成功渲染完毕后才会原子替换已有数据，旧数据的内存在逻辑准入时全额计费。外部 GPU 纹理直接进行就地（in-place）渲染，不提供类似文件导出那样的回滚保证。

## 确定性重放保证

系统采用“环境作用域内的确定性重放”作为质量策略，而非跨平台的逐比特完全一致。运行环境涵盖编译版本、数值计算依赖库、操作系统平台、不可变外部资源，对于 GPU 执行还包括显卡物理硬件与驱动程序版本。质量模式、输出格式以及所有创作输入参数同样必须保持固定。

| 作用范围 | 质量保证契约 |
| --- | --- |
| CPU 重放 | 在相同的编译版本/系统平台、外部资源、输入参数、画质模式与像素格式下，保证逐比特绝对完全一致 |
| GPU 重放 | 在固定的外部资源、输入参数、画质模式与像素格式下，保证 Seek 定位重放画面在视觉上高度稳定；允许存在微小数值浮点差异 |
| GPU 与 CPU 对比 | 绘制语义和视觉输出在各测试固件规定的容差范围内严格等价，不追求比特级一致 |
| 其他平台 / 其他显卡设备 | 不承诺跨设备无条件比特一致或容差合格；必须在目标硬件上显式执行测试固件进行验证 |

修改底层算术实现、更换编译器、切换显卡设备或升级显卡驱动均需重新执行适用的验证套件。单凭使用控制精度的 libm 浮点库并不能证明已达成跨平台绝对一致。

### 视觉验收标准

像素对比检查严格采用以下四个标准化级别之一。每个测试固件必须显式声明其采用的级别，严禁临时发明随意宽泛的比对规则。

| 级别 (Level) | 适用场景 | 验收门限 (Gate) |
| --- | --- | --- |
| Exact (精确级) | CPU 重放、CPU 黄金标准图像、带种子的确定性序列 | 逐字节完全一致 (Byte identity) |
| Numeric (数值级) | GPU 内核回读为工作 f32、打包 RGBA 与 YUV 平面 | 固件显式声明的单通道绝对误差，如线性空间 3e-4 或单个输出色阶码值 |
| Visual (视觉级) | GPU 输出对比 CPU 渲染后端 | 采用具名档位（Tier）的多指标加权比对 |
| Replay (重放级) | GPU 输出在 Seek 跳转或重复提交后对比其自身 | 采用 Replay 档位的视觉比对 |

视觉比对算法借鉴了 Skia Gold 的模糊/采样区域/Sobel 边缘匹配器以及 Khronos CTS 的位置偏差比对理念：单项全局平均数值绝不是唯一的合格标准，大分辨率图像绝不能稀释局部严重瑕疵，且允许边缘发生 1 像素的微小位移而不掩盖内容缺失缺陷。该算法在 [`visual.rs`](../../../crates/motion-render/src/gpu/visual.rs) 中实现，针对直通 Alpha 的 sRGB RGBA8 图像执行：

1. **前置条件。** 两幅图像具有完全相同的尺寸，且至少包含一个可见的非透明像素。几何固件还会额外断言 GPU 必须独立生成了其自身的覆盖率，因此空白帧或直接复用 CPU 覆盖率的结果无法通过测试。
2. **像素采样。** 每个像素贡献其 Alpha 通道以及分别在纯黑底与纯白底上合成后的显示 RGB 值，归一化到 0..1（单个 8 位色阶码值为 1/255）。低 Alpha 掩盖的色彩偏移以及因颜色相近而掩盖的 Alpha 异常在此规则下均无所遁形。两幅图像中同时透明的背景像素被排除在统计之外，避免大面积留白稀释错误。
3. **全局 RMS 均方根误差。** 在所有可见像素上计算，严格限制漫反射颜色、混合计算与渐变过渡的整体偏差。
4. **Tile 局部 RMS 误差。** 针对每个包含可见像素的 16x16 分块独立计算，精准捕获被全局 RMS 均摊掩盖的局部严重脱落缺陷。
5. **3x3 邻域离群点检测 (Neighborhood Outliers)。** 当一个像素的采样值超出另一幅图像对应位置 3x3 邻域范围加上一个松弛余量（Slack）时，该像素被判定为离群点（双向对称检验）。1 像素以内的亚像素边缘漂移判定为合法通过；而局部破洞、线条丢失、发丝断裂、裁剪泄漏以及 Alpha 通道反转均会被直接判定为失败。具体档位限制离群点占全部可见像素的最高百分比。

| 档位 (Tier) | 适用领域 | 全局 RMS | 局部 Tile RMS | 松弛余量 (Slack) | 离群点比例上限 |
| --- | --- | --- | --- | --- | --- |
| Replay | 相同后端、相同显卡设备与相同输入 | 0.002 | 0.004 | 2 个码值 | 0% |
| Paint | 纯色与渐变画刷、解析或像素对齐覆盖率上的图层混合与组不透明度 | 0.005 | 0.01 | 3 个码值 | 0% |
| Coverage | 抗锯齿路径与几何裁剪，单像素内无重叠轮廓 | 0.01 | 0.03 | 4 个码值 | 0% |
| Overlap | 相交或自相交轮廓，GPU 在 4x4 子网格上采样单像素内的重叠区域 | 0.05 | 0.12 | 8 个码值 | 3% |

具体的测试固件可按需收紧其档位中的任何单项阈值；例如 GPU 启动自检对其自相交几何保持 0.02 全局 RMS，在应用滤镜后保持 0.01。若需放宽某个档位，或引入超出 Overlap 档位的宽松用例，必须阐述明确的技术依据并同步修订本文档。上述档位门限是基于 Apple M1 Max 显卡的大量实测数据制定的：在 48 组固定种子的复杂相交测试中，最大观测值为 0.037 RMS、0.080 Tile RMS 以及 2.0% 离群点比例，而其他常规覆盖率固件均稳定低于 0.003 RMS 且完全零离群点。若在其他显卡适配器上测试失败，应当深入排查驱动或算法差异，而非随意调大容差。

系统不存在全局单通道 LSB 粗暴门限。任何容差均绝对不允许出现非有限（NaN/Inf）工作像素、几何形态缺失、绕数规则错误、裁剪泄漏或肉眼可见的闪烁。更严苛的针对特定内核的精确回归固件属于局部防劣化防护，不构成对探索新 GPU 渲染算法的限制。

CPU/GPU 之间的视觉容差绝不代表允许生成非有限像素、忽视 Alpha 通道逻辑，或者在命令提交错误未完成检查前就提前对外发布。RGBA16F 内部工作纹理或精简错误校验绝非当前支持的能力。

在创作中请务必使用显式的随机数种子、不可变资源与完备的缓存键。保序绘制不能依赖 `HashMap` 的无序遍历，也不得依赖环境全局时钟或动态字体探测。性能优化必须严格保持参考实现的运算时序；外部持有的强引用 `Arc` 以及逻辑缓存配额不代表物理内存上限。用户回调函数的纯函数性是项目架构的硬性契约，而非运行时可强制约束的沙箱。

相关属性测试、参考比对测试、特性矩阵与原生测试固件详见[开发指南](../development.md)。编译成功、无用例匹配的空测试过滤器或被忽略的测试绝不代表通过了运行时、UI、编解码器或跨平台的正式验收。
